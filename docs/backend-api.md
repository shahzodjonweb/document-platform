# Backend implementation checkpoint

The public API is `/api/v1` with no trailing slash. `contracts/public.openapi.json` is its versioned, staff-free OpenAPI 3.1 snapshot. Export it with `python manage.py export_contract`; the adjacent SHA-256 file pins the artifact for the customer repository. The spec is an explicit contract and is checked against observable API tests. It is not a claim that every roadmap endpoint exists.

## Local service behavior

Enable `DEBUG=1`, `DEVELOPMENT_LOGIN_ENABLED=1`, `ENABLE_BETA_TOOLS=1` and optionally `LOCAL_SYNC_JOBS=1`. The development login is available only from loopback and resolves to one clearly test-marked account. A normal deployment requires a configured unique `SECRET_KEY`; paid checkout and production feature release remain closed. All three plans are draft policy values copied from the handoff.

Get `/auth/session` first and send the returned `csrf_token` in `X-CSRFToken` for every unsafe cookie request, including login. The server rotates both the session key and CSRF token when signing in. Customers are stored under `customer_account_id` in the customer session; they never become `django.contrib.auth.User`. The staff realm is implemented independently under `/ops`.

A multipart `POST /files/uploads` accepts a single `file`. Inspection runs in a bounded child process. The API verifies actual page count, MIME and private binary hash and applies the server plan. `POST /quotes` accepts `feature_id`, ordered `input_ids` and tool `parameters`. The immutable quote pins policy, input fingerprints, normalized parameters and meter upper bounds. `POST /jobs` accepts `quote_id` and an `Idempotency-Key` of 8–128 characters. An identical retry returns the existing job; a changed quote with the same key returns conflict. One quote can produce only one job even when a client changes its key.

Core file tools include merge, split, extract, delete, reorder, rotate, structural compression, images to PDF, PDF to images, AES-256 protection, unlock with a known password, Word to PDF and PowerPoint to PDF. The expanded catalog also includes OCR, editable exports and PDF editing commands, documented below and in `processor-capabilities.md`. Overlapping split outputs are priced at the larger of input pages and total output pages. No-op compression releases the whole reservation. Office uploads preflight through the same isolated LibreOffice conversion to obtain exact page counts before quoting. The local bundled alpha LibreOffice runtime passed actual three-language DOCX/PPTX fixtures; production Office release remains gated on a supported engine image and no-network isolation.

Passwords never enter quote/job parameters, log events or queue payloads. Protect uses `POST /secrets` with a masked password, then passes the returned opaque ID as `secret_id` in the quote. To unlock an encrypted upload, include the password only in that upload's multipart form. It is inspected in memory and stored as a ten-minute Fernet ciphertext handle. Configure `FILE_SECRET_KEY` independently in production; the development key derives from `SECRET_KEY` with a purpose-specific domain. Handles are owner-bound, claimed by one job, and deleted on settlement or expiry. Retry after expiry requires password entry again. Source and output binaries remain encrypted as appropriate; source passwords are not retained after the attempt.

## Durable execution and usage

`python manage.py runworker` drains the transactional outbox. `--once` runs one bounded pass. Reservations, job creation and outbox publication are a single transaction. PostgreSQL locks the canonical account then grants; SQLite local development uses immediate write transactions. Database constraints prohibit overspending, duplicate request keys, duplicate quote submissions and duplicate ledger transitions.

Workers claim queued jobs under a row lock. Each execution receives a lease and a bounded parser subprocess. At-least-once queue delivery cannot settle a job twice. `dispatchoutbox` publishes pending jobs to Celery; use `celery -A config.celery:app worker` when Redis is configured. Settlement marks its outbox record complete. A queue publication failure leaves the durable event available for retry. Expired worker leases are failed and released, and private orphan output directories are removed. The commerce service reconciles provider transactions and keeps uncertain refunds pending until confirmed.

Free grants use deterministic 30-day cycles from account creation, with a UTC daily included-task cap. Purchased task grants, created only by the confirmed billing service, can cover the daily exception without raising page or feature caps. Included, referral and purchased grants have deterministic spending priority. Failing, canceling a queued job, or no-op work releases the original grant reservation; an expired grant is never revived. Running-job cancellation returns a conflict rather than releasing still-running work.

`python manage.py cleanupfiles` revokes and deletes expired binaries while retaining task metadata. It handles tracked files, terminal attempt output directories, and unregistered binaries older than 24 hours left by a crashed upload or worker. Active input jobs are protected from normal cleanup. Downloads enforce ownership, state and expiry on every request, and return attachment/no-store headers.

## Telegram integration

`python manage.py runbot` starts polling with encrypted admin-managed credentials (environment fallback is optional); it refuses to start if a webhook secret is configured. Webhooks verify `X-Telegram-Bot-Api-Secret-Token`, content type and bounded body, then persist unique update receipts. Run `python manage.py dispatchtelegram` to process a batch. Do not enable polling and webhooks for the same bot.

The adapter uses the same accounts, assets, quotes, reservations and execution services as HTTP. It supports file collection, operation selection, explicit order confirmation, quotes, execution, results, recent files, locale, plan, support and payment-support commands. Localized inline controls provide angle, DPI, format, paper and orientation. Readable `/pages`, `/split`, `/rotate`, `/format`, `/paper`, `/margin` and `/layout` commands cover exact settings; `/parameters` remains an optional advanced JSON entry. `/order` and `/remove` control numbered inputs; a new upload after quoting prompts Add to this task or Start new. Buttons bind to owner, draft and version, and quote-bound submission is idempotent across command and callback retries. Duplicate Telegram input messages have unique receipts. `/preview PAGE FILE_INDEX` and a first-page button generate actual PNG previews without usage charge. Password tools explicitly hand off to secure browser entry instead of asking for passwords in chat. Cloud download/send limits are enforced at 20/50 MiB, with web fallback for large output. No real bot token was supplied or used during implementation; real-device delivery and localized command registration remain deployment qualification work.

Mini App login verifies the official `WebAppData` HMAC, rejects duplicate fields, stale/future timestamps and replayed canonical authenticated payloads. Browser login uses a five-minute opaque challenge, a separate HttpOnly verifier cookie, explicit Telegram approval and one-time exchange. A forwarded deep link cannot be exchanged in another browser. Browser challenges do not expose account details before exchange.

## Verification

The current suite exercises actual serialized PDF outputs, exact page order, AES roundtrips, owner isolation, CSRF, canonical Telegram identity, challenge hijack/replay, tampered/stale/reordered initData, same-quote and same-key retry, quota/daily boundaries, usage restoration, retention, malicious parser inputs, worker lease recovery, separate staff roles and audit permissions. The suite runs locally on SQLite; a production PostgreSQL concurrency/load suite and OS-level no-network parser containment are still release gates.

The latest test run and root progress document provide authoritative totals; bot tests use an offline aiogram session with real domain services and real generated output files. Test data is marked development and never counts as production analytics.

## Private page preview API

`GET /files/:id/preview?page=1` and `GET /artifacts/:id/preview?page=1` return a 96-DPI PNG for one real PDF page. The asset/artifact response includes a `preview_url` when applicable. Page numbers are checked before parsing, ownership and retention are checked on every request, and the private cache is unique per source/page. PDFium runs in the bounded processing child; the API extracts only the expected, size-bounded PNG member from the validated single-page output archive. Source deletion revokes and deletes its previews. Encrypted source previews require the owner’s live encrypted password handle even when cached; their cache expiry cannot exceed that handle’s lifetime. Preview/manual review never reserves or consumes tasks.

## Expanded public domains

The generated OpenAPI snapshot contains the exact current schemas for `/studio/config`, `/generation/drafts`, `/education/projects`, `/shares`, `/workflows`, `/templates`, `/editor/documents`, `/editor/form-templates`, `/batches`, `/billing` and `/telegram/local`. Draft PATCH uses optimistic version checks. Workflow execution requires the signed confirmation returned by its quote. Batch parents retain immutable child quotes and individual outcomes; form batches bind a template version/hash.

Generation source text and saved education content are encrypted. Provider calls use strict structured output, bounded input/output, fixed service origins and no provider tools. The one exception to fixed origins is stock photos for slide decks: Pixabay's search API returns image URLs, and the worker downloads them. Those downloads are pinned to https on exactly `pixabay.com` or `cdn.pixabay.com` (every redirect hop re-checked), capped in bytes and pixels, and re-encoded as a plain JPEG with no EXIF before they reach a deck. Searches always send `safesearch=true`, are cached for 24 hours by a hash of the query, and happen only inside a confirmed job. Results are ranked by how many words of the slide's photo subject their tags share, and those sharing none are dropped; the model is then shown the best few for each slide as small re-encoded previews (never Pixabay URLs) beside the slide's text, and picks one or none. That call is recorded as a provider attempt with stage `photo_pick`; if it cannot be made or fails, the best tag match is used instead. A photo that cannot be fetched, or that no candidate fits, leaves its slide drawn as text; it never fails the job. Selected-section revisions fork an owned source and preserve all unselected sections. Branding resolves only owned, size-bounded local image assets; it cannot fetch arbitrary URLs. Deck photos are free to the customer and limited per deck by the plan's `max_deck_images`; the admin turns them on with a Pixabay key and can switch them off at once.

Stars sandbox activation requires DEBUG, explicit opt-in and a test account. Sandbox facts are excluded when those conditions stop applying. Live offers require versioned, reviewed server prices; clients cannot choose invoice amounts. Local bot calls are development-only and invoke actual handlers with a transport that cannot send to Telegram. Admin credentials, audit records and staff routes are absent from the public contract.
